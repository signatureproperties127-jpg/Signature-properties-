SIGNATURE PROPERTY — LEAD-WISE OPERATING SYSTEM
MASTER IMPLEMENTATION PROMPT

IMPORTANT:
This is NOT a redesign of the existing V2 architecture.

Phases 1–20 are already completed/certified.
Do NOT rewrite completed phases.
Do NOT create another Lead/Client model.
Do NOT create another Requirement model.
Do NOT create another Form Engine.
Do NOT create duplicate APIs.

The objective is to make the entire CRM OPERATE LEAD-WISE from the
agent's perspective while preserving the existing normalized backend
entities.

============================================================
3. NON-NEGOTIABLE BUSINESS RULES
============================================================

RULE 1:

One Client = One Lead.

Never create a second Lead for the same client merely because the
client has another requirement.

RULE 2:

Same requirement changes:

UPDATE REQUIREMENT.

Keep the SAME RequirementID.

Example:

R000001

Before:
3 BHK
₹2 Cr
Vesu

After client conversation:
2 BHK
₹80 Lakh
Vesu

Still:

R000001

Never create R000002 for this change.

RULE 3:

Genuinely different need:

NEW REQUIREMENT.

Example:

Existing:

R000001
Purchase → Residential → Flat

Client now says:

"I also need a Commercial Office."

Create:

R000002
Purchase → Commercial → Office

Same Lead.
New Requirement.

RULE 4:

Inventory is GLOBAL.

Do NOT copy/create duplicate property records inside every Lead.

Instead:

Lead
→ Requirement
→ Matching
→ Inventory Property
