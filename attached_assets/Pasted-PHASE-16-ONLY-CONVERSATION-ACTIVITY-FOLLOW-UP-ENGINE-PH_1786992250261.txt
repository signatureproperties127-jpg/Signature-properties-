PHASE 16 ONLY — CONVERSATION / ACTIVITY / FOLLOW-UP ENGINE

PHASES 1–12 ARE COMPLETE.
PHASE 13 IS DEFERRED.
PHASES 14–15 MUST NOT BE REDESIGNED OR REPEATED.

Implement ONLY Phase 16.

OBJECTIVE

Build the conversation-driven Activity + Follow-up layer.

The CRM should remember what happened when an agent interacted
with a client and should connect the conversation to the correct
Client, Transaction and Requirement.

CORE MODEL:

ONE CLIENT = ONE LEAD
        ↓
TRANSACTION
        ↓
REQUIREMENT / NEED
        ↓
CONVERSATION / ACTIVITY
        ↓
FOLLOW-UP

IMPORTANT:

Conversation is NOT a new Lead.
Conversation is NOT a new Requirement.
An activity must never create a duplicate Client.

==================================================
2. CONVERSATION CAPTURE
==================================================

Agent should be able to record:

What happened?

Example:

"Client said ready-to-move property preferred."

What did we learn?

Possession:
Ready to Move

Urgency:
Immediate

Parking:
2

Next action:

"Send 3 matching properties"

Follow-up:

Tomorrow 11:00

The system must update the EXISTING Requirement where
the agent explicitly chooses a Requirement.

Do NOT create another Requirement.

==================================================
3. REQUIREMENT UPDATE
==================================================

When conversation captures:

Possession = Ready to Move

the system should PATCH:

PATCH /api/requirements/:requirementId

Only supplied fields are changed.

Existing fields remain untouched.

UNKNOWN → KNOWN.

KNOWN → updated KNOWN value.

NOT_APPLICABLE remains distinct.

Never convert UNKNOWN to NO automatically.

==================================================
4. ACTIVITY + REQUIREMENT HISTORY
==================================================

A conversation that changes a Requirement must create:

1. Activity record
2. RequirementHistory record

Example:

Activity:
"Called client"

RequirementHistory:
Possession:
UNKNOWN → KNOWN("Ready to Move")

Both must be linked to:

LeadID
TransactionID
RequirementID

Use existing RequirementHistory architecture.

Do not create duplicate history entries.

==================================================
9. NEXT ACTION
==================================================

After conversation, show:

NEXT ACTION

Example:

"Confirm possession by tomorrow."

or

"Send matching properties."

This is an Activity/Follow-up concept.

Do not confuse it with Phase 11 Next Question Engine.

NEXT QUESTION:
"What should I ask the client?"

NEXT ACTION:
"What should the agent do next?"

They are different.
