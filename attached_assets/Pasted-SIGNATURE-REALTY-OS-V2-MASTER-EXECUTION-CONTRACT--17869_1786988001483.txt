1. FINAL BUSINESS MODEL — ABSOLUTE
==================================================

The business model is:

CLIENT = LEAD

LEAD
  |
  +-- TRANSACTION 1
  |      |
  |      +-- REQUIREMENT 1
  |      +-- REQUIREMENT 2
  |
  +-- TRANSACTION 2
         |
         +-- REQUIREMENT 3

Rules:

1. One real client = one permanent Lead.
2. One Lead can have many Transactions.
3. One Transaction can have many Requirements.
4. Requirement.LeadID MUST equal Transaction.LeadID.
5. Requirement does NOT store inventory/property data.
6. Matching remains a separate relationship between Requirement and Property/Inventory.
7. Requirement is a living client need.
8. Requirement can start extremely small.
9. UNKNOWN is a valid state.
10. Missing information is NOT an error.
11. Never force the agent to complete a giant form.
12. Never create a new Requirement just because a client answers another question.
13. Progressive information must update the SAME RequirementID.
14. Client conversation is what gradually enriches the Requirement.
15. The system must adapt to the client's actual need.
